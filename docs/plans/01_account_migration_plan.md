# 01_account_migration_plan.md (기존 직원 및 과거 주문 이력 연동 기능)

## 🎯 목표
1. 새로 발급된 이메일 계정(Supabase Auth)을 기존 직원(이름+핸드폰 끝자리)과 짝지어 연결합니다.
2. 과거에 해당 직원이 주문했던 모든 이력(`orders`)을 새 이메일 계정으로 소유권 이전하여, 마이페이지에서 과거 내역을 정상적으로 볼 수 있게 합니다.
3. 연동이 완료된 직원이 **최초 로그인 시**, 관리자님이 보시던 Supabase 대시보드(Users 탭)의 `Display name` 열에도 해당 직원의 이름이 자동으로 채워지도록 합니다.

## 📝 상세 구현 계획

### 1. 관리자 패널 (AdminPanel.jsx) 수정
- **UI 추가**: [직원 계정 연동] 이라는 새로운 모달 팝업 추가.
- **입력 폼**: 
  1. 가입된 직원 이메일 직접 입력란 (ex. info@janytree.com)
  2. 연동할 기존 직원 선택 드롭다운 (ex. 홍길동(1234), 김철수(5678))
- **실행 로직**:
  - 입력한 이메일로 가입된 회원의 `User ID(UUID)`를 찾습니다.
  - 해당 User ID와 기존 직원의 이름을 사용하여 `employee_profiles` 테이블에 공식 직원 데이터로 등록(연동)합니다.
  - 과거 주문 테이블(`orders`)에서 기존 직원의 `member_id`로 작성된 모든 주문을 찾아, 새로운 `user_id`로 일괄 업데이트(소유권 이전)합니다.

### 2. 자동 이름 동기화 로직 (Home.jsx 등)
- 직원이 로그인할 때마다 현재 계정에 `Display name`이 비어있는지 확인합니다.
- 비어있다면, 관리자님이 방금 연동해주신 `employee_profiles`의 이름을 가져와서 자기 자신의 계정에 쏘아 넣어(`updateUser`) Display name을 자동으로 동기화합니다. 

## ⚠️ 확인 필요 사항 (User Review)
Supabase 보안 규칙상, 관리자라 하더라도 웹 브라우저에서 '다른 사람의 이메일이나 이름'을 마음대로 수정하거나 목록을 전체 조회하는 것은 금지되어 있습니다. 
따라서 관리자 페이지에서는 **"새로 발급하신 직원의 이메일"을 직접 타이핑**하고, 아래쪽의 **"기존 직원(이름+전화번호) 목록" 중 하나를 드롭다운으로 선택해서 [연동하기] 버튼을 누르는 방식**으로 안전하게 진행해야 합니다. 이 방식으로 UI를 만들어도 괜찮으실까요?
